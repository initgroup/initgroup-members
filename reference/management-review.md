# 경영 현황·프로젝트·인력 보드 검토

검토일: 2026-10-24. 사용자 제공 화면 4개와 프론트·백엔드·SQL 조회 흐름을 함께 검토했습니다. 후속 연간 기능에서는 승인된 스키마 이관과 롤백 전용 DB 검증을 수행했습니다. 비밀 파일은 열람하지 않았습니다.

| 항목 | 확인 내용 | 반영 |
| --- | --- | --- |

## 다음 개선 우선순위

이번 작업에서 등록 투입과 홈 손익의 연결까지 반영했습니다. 다음은 추가 개선 항목입니다.

1. **회계 실적 연계**: 현재 실적은 사용자 기준인 계약 이후 사업의 월별 투입단가 집계입니다. 회계상 인식 매출·비용과 비교하려면 회계 전표나 수금 자료를 별도로 연결해야 합니다.
2. **기존 별도 계획안 정리**: 기존 자료는 보드 참고 조회로 보존하고 운영 집계에는 합산하지 않습니다. 과거 계획안에만 있는 배치가 있다면 검토 후 운영 프로젝트에 반영할 수 있으나 이번 작업에서 자동 이관·삭제는 하지 않았습니다.
3. **의사결정 지표 보강**: 사업부·팀원별 연간 목표 대비 매출, 프로젝트 원본 수주 현황과 회사 연간 비용을 차감한 연간 관리 순이익은 연간 목표·실적 메뉴에 반영했습니다. 전년 동기 비교, 향후 3개월 가용량, 종료 임박 프로젝트는 추가 개선 항목입니다. 목표값을 임의로 설정하지 않습니다.
4. **과부하와 중복 배치 구분**: 여러 프로젝트에 0.5 M/M씩 배치하는 것은 중복이지만 과부하는 아닙니다. 보드의 기존 중복 알림과 이번 요약의 월 1 M/M 초과 경고는 다른 의미입니다. 향후 휴가·휴직·시간제 근무를 반영하려면 월별 개인 가용량의 원본 데이터가 필요합니다.
5. **위험 후속 조치**: 현재 위험의 바로가기는 해당 연도의 보드로 이동합니다. 특정 인력·프로젝트·월로 필터링하고 강조하는 기능을 추가하면 확인 시간이 더 줄어듭니다.

## 검증 범위

- 백엔드 단위 테스트 68개, 소스·SQL ID·바인드 계약 검사 통과. 상태 전환·취소 제외·연도 절단·원 단위 반올림·단건/일괄 저장의 상태 강제 적용을 검증했습니다.
- 실행 중인 로컬 서비스의 `GET /api/health` HTTP 200 확인.
- JavaScript 회귀 테스트: 홈의 빈 계획·정밀 금액·오류 복구, 프로젝트별 중복 제거·계획/확정 분리·삭제 대기 제외, 부서 순서·미지정·협력업체 분리, 전체 프로젝트를 반영한 가용량과 과부하.
- 실제 Edge 브라우저에 합성 데이터를 공급해 연간 목표·회사 연간 비용 저장, 영역별 입력 보존·버전 충돌, 연도 마감과 프로젝트 개별/전체 펼침, 편집 모드 진입 시 펼침, 인력 개인/사업부 전환, 검색 빈 결과, 복수 배치, 상세 모달 열기·드래그·미저장 닫기·Esc·페이지 이탈, 조회 실패 시 이전 내용 차단, 저장 요청, 390px 모바일 폭, 홈 바로가기와 연간 손익 표를 확인했습니다. 보드 보기 전환은 GET 외 요청을 발생시키지 않는 것도 확인했습니다.
- 운영 로그인 세션은 사용하지 않았습니다. 화면 검증은 합성 응답을 사용하며 DB 검증은 미사용 연도에서 수행하고 전부 롤백합니다.

연간 목표 입력은 직원별 연간 금액을 기준으로 단순화했습니다. 사업부·회사 추가목표는 선택 입력이고 회사 목표에 한 번씩만 더합니다. 목표와 회사 비용은 영역별 저장을 제공하며 메인의 연간 목표·비용·달성률도 같은 집계를 사용합니다. 목표·비용은 연간 입력합니다. 메인은 비교용 월 환산 목표와 월별·누적 수행 매출을 함께 표시하고 프로젝트·투입 종료 이후 매출을 제외합니다. 회사 비용은 연간 손익에서 한 번만 차감합니다.
